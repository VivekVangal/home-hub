## Recently resolved

- [x] **VDOT training paces added alongside Riegel.** Riegel (in `analyzeGoal`) still predicts race-day finish time — a different question VDOT isn't meant to answer better. VDOT now derives a single fitness score from the same recent-race input and produces five distinct training paces (easy/marathon/threshold/interval/repetition) using Daniels & Gilbert's actual published regression equations (not an interpolated table), verified against the well-known VDOT-50-is-about-a-20:00-5k reference point. Quality-session notes now cite threshold/interval pace instead of one blended "stretch pace," and easy/long-run notes cite the VDOT easy pace — falling back to the old wording exactly when there's no recent race result to derive VDOT from. `computeVdot`/`vdotZonePace`/`vdotTrainingPaces` in `lib/trainingPlan.js`, tests in `trainingPlan.test.js` (including running the actual module in plain `node` to double check numbers, since vitest couldn't execute in this sandbox — see below).
- [x] **Training plan is now dynamic.** `computeTrainingAdjustment()` in `lib/trainingPlan.js` takes the last 3 weeks of already-logged sessions and adjusts upcoming weeks on regeneration: skipping more than a third of recent sessions slows the mileage ramp (never speeds it up — consistency is what should be rewarded), and consistently running logged sessions at or faster/slower than the stretch-goal pace nudges that goal by up to 3%. "Regenerate remaining plan" on the Training page now shows a note explaining what changed and why, when something did. Unit tests in `trainingPlan.test.js` (the adjustment function + `buildTrainingPlan` integration) and `TrainingPage.test.jsx` (`describeAdjustment`'s message text).
- [x] `scripts/setup.sh` step 3 idempotency bug — `ensure_firebase_project` now treats "already exists" as a successful no-op (instead of a hard `exit 1`) whether it's detected via `projects:list` or only surfaces when `projects:create` itself fails with that message. Covered by `scripts/setup.test.sh` (a plain-bash test with a stubbed `firebase` command — no test framework existed for shell scripts before this, only vitest for JS).
- [x] ~~Terra integration~~ — **evaluated and removed.** Was briefly built as a unified aggregator (Garmin/Fitbit/Apple Health/Oura/etc. through one API) to work around Strava's 10-athlete cap, but its actual pricing turned out to start at $399-499/month with no free tier at all (just a 30-day refund window) — not viable for a household hobby project. Code (`functions/terra.js`, `lib/terra.js`, the Training page UI block) was fully deleted rather than left dead in the repo. Replaced by direct, free integrations for Apple Health and Garmin instead.
